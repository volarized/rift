Rift is an agentic development toolkit for reading, discovering, and editing codebases.

Rift gives [MCP](https://modelcontextprotocol.io/specification/2026-07-28) agents structured reads
and precise, precondition-guarded edits over Rust code in the current folder.

## Install

Linux and macOS:

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://volar.sh/rift/install.sh | bash
```

Windows PowerShell:

```powershell
irm https://volar.sh/rift/install.ps1 | iex
```

The installer downloads the latest verified release for your platform and installs it for the
current user. To install a specific version, set the `RIFT_VERSION` environment variable to its
release tag.

## MCP configuration

An MCP client launches `rift mcp` in the folder containing the codebase. Register it in the
client's MCP configuration — for Claude Code, `.mcp.json` in the project root:

```json
{
  "mcpServers": {
    "rift": {
      "command": "rift",
      "args": ["mcp"]
    }
  }
}
```

## Rust index

`rift mcp` starts a native filesystem watcher before it scans the current folder. The initial scan
runs in a bounded blocking task managed by Tokio, so filesystem traversal and tree-sitter parsing do
not block the async MCP executor.

External writes and Rift changes advance the same workspace change counter and enter one serialized
rebuild lane. Before each current-tree read, the server reconciles watcher state against an exact
fingerprint of the admitted workspace files and waits until the published index has caught up.

The server publishes the read index and admitted configuration together as one immutable snapshot.
Each request retains its captured snapshot while later rebuilds publish newer ones, so a read never
combines files or policy from different workspace states.

The scanner skips symlinks and the `.git`, `.rift`, and `target` directories. It writes no index or
projection state to the codebase.

`rift mcp` writes tracing events to stderr. Stdout carries MCP frames, so diagnostics never enter the
protocol stream.

The MCP server advertises the read tools:

- `search` finds declarations and matching source lines.
- `get_symbol` returns declarations with source excerpts when the name is known.
- `nodes` lists the syntax nodes covering one byte position, outermost first. Each node id ends
  in a witness — a hash of the node's source bytes — which is what a later `replace_node`
  verifies before writing.

## Changes

The change tools edit the workspace. Each resolves its address against the served snapshot, proves its
preconditions against the bytes on disk, and only then writes — atomically, behind one
application lock, so two concurrent changes collide as a clean refusal rather than as
interleaved bytes:

- `replace_symbol` rewrites one declaration addressed by symbol; the parser derives the span.
- `insert_symbol` lands a new declaration before or after its anchor, or content at a file
  target; `create_missing` creates a missing file target first.
- `replace_node` replaces one syntax node through a witnessed address from `nodes`; a stale
  witness refuses with the expected and observed values.
- `patch` applies unified-diff hunks, several files in one change; a context mismatch refuses
  and the tree stays untouched.

A change that cannot land returns a refusal naming the failed precondition, and the tree is
untouched. An applied change re-parses what it touched and reports parser findings on the
result. Every failure carries a stable error code and a suggested action.

## Update

```sh
rift update
```

The command downloads the latest checksummed native release into a temporary staging directory,
validates its version, then replaces the current executable. Unix uses a same-folder atomic rename;
Windows keeps a rollback binary until replacement starts.

```text
agentic development toolkit

Usage: rift [COMMAND]

Commands:

Options:
  -h, --help     Print help
  -V, --version  Print version
```
