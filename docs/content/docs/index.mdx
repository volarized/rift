Rift is an agentic development toolkit for reading, discovering, and editing codebases.

Rift gives [MCP](https://modelcontextprotocol.io/specification/2026-07-28) agents structured reads
over Rust code in the current folder.

## Install

Linux and macOS:

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://volar.sh/rift/install.sh | bash
```

Windows PowerShell:

```powershell
irm https://volar.sh/rift/install.ps1 | iex
```

Each installer resolves the latest release, selects a native x86-64 or Arm64 archive, and verifies
its SHA-256 checksum before installing `rift` for the current user. Set `RIFT_VERSION` to a release
tag to install that release explicitly.

## MCP configuration

An MCP client launches `rift mcp` in the folder containing the codebase. This repository includes
the following `.mcp.json` configuration:

```json
{
  "mcpServers": {
    "rift": {
      "command": "cargo",
      "args": ["run", "--quiet", "--", "mcp"]
    }
  }
}
```

Use `"command": "rift"` and `"args": ["mcp"]` after installing the release binary.

## Rust index

`rift mcp` reads `.rs` files from the current folder into one immutable in-memory snapshot.
Tree-sitter extracts Rust declarations and syntax nodes, while the typed provider composition records
the source-to-syntax-to-index pipeline.

The scanner skips symlinks and the `.git`, `.rift`, and `target` directories. It writes no index or
projection state to the codebase.

The MCP server advertises these read tools:

- `search` finds declarations and matching source lines.
- `get_symbol` returns declarations with source excerpts when the name is known.

## Update

```sh
rift update
```

The command downloads latest checksummed native release into a temporary staging directory,
validates its version, then replaces current executable. Unix uses a same-folder atomic rename;
Windows keeps a rollback binary until replacement starts.

Commands:
