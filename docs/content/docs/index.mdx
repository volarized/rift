Rift is an agentic development toolkit for reading, discovering, and editing codebases.

Rift provides [MCP](https://modelcontextprotocol.io/specification/2026-07-28) agents structured
reads and edits for various programming languages in the project workspace.

<Callout type="info">
Currently, only Rust is supported, but more languages will be added in upcoming releases.
</Callout>

## Install

<PlatformTabs>

<Tab value="Linux and macOS">

```sh
curl --proto '=https' --tlsv1.2 -fsSL https://volar.sh/rift/install.sh | bash
```

</Tab>

<Tab value="Windows PowerShell">

```powershell
irm https://volar.sh/rift/install.ps1 | iex
```

</Tab>

</PlatformTabs>

The installer downloads the latest verified release for your platform and installs it for the
current user. To install a specific version, set the `RIFT_VERSION` environment variable to its
release tag.

## MCP configuration

An MCP client launches `rift mcp` in the folder containing the codebase. Register it in the
client's MCP configuration - for Claude Code, `.mcp.json` in the project root:

```json
{
  "mcpServers": {
    "rift": {
      "command": "rift",
      "args": ["mcp"]
    }
  }
}
```

## Reads

Rift reads the source files in the folder where the MCP client launches `rift mcp`. Later calls
include edits made through Rift, your editor, a formatter, or another process.

### Search

When you know what the code does but not its name, ask your agent to search for it:

> Use Rift to find all information about server startup.

The agent calls [`search`](/docs/protocol/mcp#tool-search) with the query `server startup`, which
returns matching declarations and source lines with their paths.

### Retrieve symbol

When you know the declaration name, ask for it directly:

> Use Rift to retrieve the `ReadService` declaration.

The agent calls [`get_symbol`](/docs/protocol/mcp#tool-get_symbol), which returns the declaration
and its source excerpt. It can pass a returned path and byte position to
[`nodes`](/docs/protocol/mcp#tool-nodes) when it needs the surrounding syntax structure.

The [MCP reference](/docs/protocol/mcp#reads) defines request fields and result shapes for client
integrations. The [index architecture](/docs/architecture#index) explains how Rift keeps those
reads aligned with filesystem changes.

## Edits

The change tools edit the workspace. Each resolves its address against the published index, proves
its preconditions against the bytes on disk, and only then writes - atomically, behind one
application lock, so two concurrent changes collide as a clean refusal rather than as
interleaved bytes:

- [`replace_symbol`](/docs/protocol/mcp#tool-replace_symbol) rewrites one declaration addressed by
  symbol; the parser derives the span.
- [`insert_symbol`](/docs/protocol/mcp#tool-insert_symbol) lands a new declaration before or after
  its anchor, or content at a file target; `create_missing` creates a missing file target first.
- [`replace_node`](/docs/protocol/mcp#tool-replace_node) replaces one syntax node through a
  witnessed address from `nodes`; a stale witness refuses with the expected and observed values.
- [`patch`](/docs/protocol/mcp#tool-patch) applies unified-diff hunks, several files in one
  change; a context mismatch refuses and the tree stays untouched.

A change that cannot land returns a refusal naming the failed precondition, and the tree is
untouched. After a change applies, the server re-parses what it touched and reports parser
findings on the result. Every failure carries a stable error code and a suggested action.

## Update

```sh
rift update
```

The command downloads the latest verified release for your platform and replaces the current
executable.
