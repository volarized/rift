Rift is an agentic development toolkit for reading and discovering codebases.

Rift provides [MCP](https://modelcontextprotocol.io/specification/2026-07-28) agents structured
reads for various programming languages in the project workspace.

<Callout type="info">
Rift supports Rust, Python, JavaScript and TypeScript (including TSX), Markdown, JSON, YAML, and TOML.
</Callout>

[Installation](/docs/installation) connects Rift to your MCP client.
[Agentic usage](/docs/agentic-usage) installs the skill that teaches Claude Code which tool to call.
The [MCP surface](/docs/mcp) defines each tool and resource.
The [codebase intelligence](/docs/codebase) diagram shows how source and provider facts contribute to a read.

## Reads

Rift reads the source files in the folder where the MCP client launches `rift mcp`. Later calls
include filesystem changes made by a formatter or another process.

### Search

When you know what the code does but not its name, ask your agent to search for it:

> Use Rift to find all information about server startup.

The agent calls [`search`](/docs/mcp#tool-search) with the query `server startup`, which
returns matching declarations and source lines with their paths.

### Retrieve symbol

When you know the declaration name, ask for it directly:

> Use Rift to retrieve the `ReadService` declaration.

The agent calls [`get_symbol`](/docs/mcp#tool-get_symbol), which returns the declaration
and its source excerpt. It can pass a returned path and byte position to
[`nodes`](/docs/mcp#tool-nodes) when it needs the surrounding syntax structure.

The [MCP reference](/docs/mcp#reads) defines request fields and result shapes for client
integrations. The [index architecture](/docs/developer/architecture#index) explains how Rift keeps those
reads aligned with filesystem changes.
