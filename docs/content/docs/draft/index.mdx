---
title: Rift
---

Rift is an agentic development toolkit: a set of tools and utilities that helps people and agents
work with codebases. It uses code structure and surrounding context to give agents deeper reads,
spend fewer tokens on finding relevant code, and make precise edits.

Agents use Rift through [MCP](https://modelcontextprotocol.io/), the protocol their harness uses
to discover and call tools. A Rift server operates on one **workspace**: the folder on your
machine that contains the codebase.

Changes can land directly in that folder. When work needs to stay separate, the agent creates a
**projection**: a pinned copy of the workspace, similar to a Git worktree but without requiring
Git. A projection is an ordinary folder, so agents and existing tools such as formatters and
linters can work inside it. Rift writes its changes back to the workspace only when the agent
publishes the projection.

Most implementation detail below matters only to server and protocol implementers. These pages
explain the parts needed to inspect that behavior:

- [Architecture](/docs/draft/architecture) — how Rift works, which processes it runs, and how
  ownership is distributed across them
- [Configuration](/docs/draft/configuration) — the `rift.toml` file used to customize Rift's
  behavior and connect additional tools and providers
- [Protocol](/docs/draft/protocol) — the logical entities, MCP and SCIP surfaces, and metadata
  Rift defines
