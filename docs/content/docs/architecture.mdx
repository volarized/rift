## Sessions

Each MCP client launches `rift mcp` with a workspace path. The bridge starts the workspace server or
connects to the server already responsible for that directory.

The bridge opens one session, and that session owns one writable projection. One live MCP connection
may use a session at a time. Its projection remains available across disconnects and server restarts
until the session is removed.

The server coordinates sessions, Rift FS, language adapters, and publication.

## Rift FS

Rift FS is the persistent filesystem layer for workspace projections. It exposes a projection below
`<workspace>/.rift/projections` when an adapter or filesystem tool needs a path. That exposure and its
lifecycle remain internal to Rift.

Each projection is a live workspace view. An untouched path follows the workspace. After a session
changes a path, its version remains isolated while other workspace changes continue to appear on
untouched paths. A directory change covers its descendants.

Every visible projection state has a `ProjectionHead`. The head advances after an acknowledged MCP
change, an acknowledged Rift FS operation, a restore or publication, and a workspace change visible
through an untouched path. Reads at one head observe one ordered state. Language adapters refresh
their derived state before answering for a newer head.

Acknowledged projection changes, dirty paths, and the current head survive bridge disconnects and
server restarts. A failed persistence step leaves the previous acknowledged state and head intact.

Projection creation and clean restore scale with changed data. Storage and publication scale with
affected paths and changed bytes. Access to one untouched file reads only the required path.

## Reads and changes

Rift reads the projection tree directly. Language adapters analyze the same projection and return
symbols, relationships, diagnostics, actions, and validation results.

MCP changes name the head they observed and apply atomically. A change fails before mutation when the
head has advanced. Filesystem operations through Rift FS are ordered and advance the head after each
acknowledged operation; a tool that changes several files may expose intermediate heads.

## Publication

`publish` applies the session's reviewed changes to the workspace. It operates on one stable
projection head, so projection mutations cannot interleave with it.

Rift refuses to replace a changed path when its workspace value also changed while the session's
version was isolated. A changed directory includes its subtree.

Rift forms the resulting workspace tree and validates it before applying the changed paths. A
conflict or failed validation leaves the workspace and projection unchanged. Success applies all
changed paths, refreshes the projection from the workspace, marks it clean, and returns a fresh head.
Unrelated workspace changes remain visible.

Rift serializes its own publications and checks affected paths as they are applied. After an
interrupted publication, recovery completes either the published tree or the tree that preceded it
before accepting more work.

## Restore and removal

`projection_restore` refreshes selected changed paths from the workspace, or every changed path when
none are selected. It returns a fresh head. Session removal discards the retained projection. Clean
and dirty inactive sessions remain until explicit removal.
