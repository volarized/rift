---
title: MCP
---

`rift mcp` maps MCP JSON to the local Rift service. One bridge process owns one session connection.

## Connection

The bridge starts or finds the server for the requested workspace, creates a session id, and opens
`Connect`. `Connected` returns the workspace path, session, current `ProjectionState`, and a
connection id used by later calls.

One session admits one live connection. A disconnected session is retained and may be continued or
removed. Rift FS exposes its projection when another process or adapter needs a path.

## Reads

The discovery tools read the current session projection:

| Tool | Result |
| --- | --- |
| `outline` | declarations in one file |
| `search` | ranked files, nodes, or symbols |
| `match` | literal, regular-expression, or structural matches |

Resources provide larger or reusable payloads:

| Resource | Content |
| --- | --- |
| `rift://workspace{?cursor}` | projection state, capabilities, limits, and validators |
| `rift://fs{/path}{?start,length,cursor}` | directory entries or bounded file content |
| `rift://symbol/{language}/{name}{?cursor}` | semantic facts for one symbol |
| `rift://actions/{address}{?only,cursor}` | actions offered at an address |
| `rift://action/{token}` | one action and its argument schema |

Reads return the `ProjectionHead` they used. Cursors continue one captured result order and expire
when the server releases it.

## Changes

`edit`, `patch`, `rewrite`, `rename`, `move`, `delete`, `change_signature`, and `act` change the
session projection. Each request supplies the expected `ProjectionHead`.

Rift resolves and validates the complete operation before making it visible. The result is one of:

- applied, with a fresh projection state and evidence;
- refused, with a stable reason and diagnostics.

A stale head returns `projection_head_moved` with the current head. `projection_restore` restores
selected changed paths from the workspace, or every changed path when none are selected. `publish`
compares affected workspace paths and either writes all changes or returns the conflicting paths.

## Execution

`execute` evaluates a code block in a disposable workspace derived from the session projection.
`debug_start`, `debug_get_frame`, and `debug_stop` provide bounded post-mortem inspection. Writes
made by evaluated code are discarded.

Execution is enabled only when both workspace configuration and the language adapter allow it.

## Errors

Domain refusals are normal tool results. `ErrorData` is reserved for invalid requests, expired
cursors, stale heads, unavailable adapters, limits, timeouts, storage failures, and similar call
failures. Its retry directive tells the caller whether to change the request, retry it, refresh the
projection, or wait for operator action.
