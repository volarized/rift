Rift works in a workspace only if git is enabled there, which is true of virtually every repository. If
it isn't, run `git init` in the workspace. Requiring it enforces a practice you want anyway.

The model has three axes:

- **temporal** — revisions
- **semantic** — symbols
- **physical** — files, as syntax trees, with leaves

## Revision

By default Rift indexes and works with the current revision: the default branch, at its latest commit.

Every tool and every resource also takes an optional `rev` argument that points somewhere else. It is a
git revision parameter — [`gitrevisions(7)`](https://git-scm.com/docs/gitrevisions) — so anything git
accepts on a command line works here:

| `rev` | Points at |
| --- | --- |
| *(omitted)* | default branch, latest commit |
| `main`, `refs/heads/main` | a branch |
| `v1.2.0`, `tags/v1.2.0` | a tag |
| `dae86e1` | a commit |
| `worktrees/feature-x/HEAD` | a linked worktree |
| `main-worktree/HEAD` | the main worktree |
| `HEAD~3`, `main@{yesterday}` | anything else the syntax allows |

The worktree spellings are git's own: per-worktree refs are reachable from any other worktree as
`worktrees/<id>/HEAD` and `main-worktree/HEAD`. Incremental work lands in a worktree, so naming one is
how you ask about a change that isn't on a branch yet.

A `rev` names bytes, not meaning. The same commit means different things to a compiler depending on which
dependencies are installed, so every response reports the revision *and* the environment it resolved to.
Pass those back when two calls have to agree.

## Symbol

A symbol is any entity of a given language that carries compiler-provided metadata, at a given revision.
Think of classes, functions or methods as examples of symbols. An arbitrarily large codebase can have
thousands of them.

What the rift server does well is indexing those symbols, the relationships between them, and other
compiler-driven facts — for instance the list of dependants and dependencies.

A declared type is a symbol as well. `struct Config` and `interface Props` are declarations like any
other, and they carry the `type` facet. Languages without types still have symbols.

A symbol is identified by the URI that resolves it:

```
rift://symbol/python/pkg/util.py:load_config
```

Symbols live across revisions. That identity is the symbol itself, at whichever revision the request
resolved; attach `?rev=` to pin it to one:

```
rift://symbol/python/pkg/util.py:load_config?rev=v1.2.0
```

The full shape is [`Symbol`](#Symbol) in the reference below.

## Leaf

Physically, a codebase is files, and each file is a
[concrete syntax tree](https://en.wikipedia.org/wiki/Parse_tree) — every token the source contains, in
the shape the grammar gives it. A leaf of that tree is where a symbol is physically written.

So a symbol is a semantic object, and its leaves are the places it is defined and mentioned. One symbol,
many leaves.

A leaf is identified by where it sits: the file, and the byte range it spans.

```
rift://leaf/python/pkg/util.py@1204-1266
```
