---
title: Core
---

The core schema contains values shared by MCP and language adapters. It describes projection
concurrency, source structure, semantic facts, and changes.

## Projection state

`ProjectionHead` is an opaque token for the current session view. `ProjectionState` contains:

```json
{
  "head": "ph_…",
  "dirty": true
}
```

The head advances whenever the visible projection state changes. Reads use the current session
projection, and changes carry the head they expect.

## Paths and files

`ProjectPath` is a normalized UTF-8 path relative to the workspace root. It uses `/`, contains no
`.` or `..` component, and never addresses `.rift`.

`ProjectEntry` describes a directory, regular file, or symlink. Regular-file content records size
and executable mode. Symlink targets are bytes. The filesystem resource carries file bytes as
UTF-8 or base64 and lists directory entries.

Directories are derived from the path tree. Source changes cover regular files, symlinks, modes,
and paths.

## Source locations

`TextRange` uses half-open UTF-8 byte offsets. `SourceSpan` combines a file with a range. `NodeId`,
`SymbolId`, `MatchId`, and `ActionOfferId` address facts in the session projection.

Opaque match and action ids are valid only for the projection head that produced them. A later head
requires discovery again.

## Semantic facts

Adapters return:

- symbols and syntax nodes;
- relationships between them;
- signatures, types, and documentation;
- diagnostics and coverage.

Coverage distinguishes “nothing matched” from “the adapter could not inspect enough source to
know.” Consumers must use it when interpreting empty or partial results.

## Changes

`Edit` contains source operations such as text replacement, file creation, deletion, and movement.
Higher-level operations resolve to an atomic edit set plus preconditions, effects, diagnostics, and
validation evidence.

Rift applies the set only while the supplied `ProjectionHead` is current. A successful change
returns a fresh `ProjectionState`. A semantic refusal is a typed result; transport and
infrastructure failures use `ErrorData`.

The full field definitions are in the generated [reference](/docs/protocol/reference).
