An adapter is how a language gets into Rift: a process wrapping that language's real compiler, and
answering questions about it. The Rift server drives it over **gRPC on a Unix domain socket**, and the
contract is `protocol/adapter.proto`.

## Transport

One Rift server starts its adapters, one per language, and owns them. Nothing else connects to them.
That decides more of this page than anything else: a workspace has exactly one party creating,
refreshing and closing it, so the adapter arbitrates nothing.

One adapter still holds several workspaces at once, because many agents work against one repository.
So in-flight work is bounded per workspace rather than per process, and the adapter interleaves
streams rather than draining one before starting the next — one agent's large analysis must not stall
everyone else on the connection.

Because the transport is gRPC, this contract carries no framing of its own. There is no envelope, no
request id, no operation name, no sequence number and no cancel call: an RPC method *is* the
operation, a stream is ordered, and a cancelled context or an expired deadline ends the work. Failures
are `google.rpc.Status`, carrying `Refusal` or `StaleState` in `status.details`.

## The adapter gets a worktree

rust-analyzer, gopls and tsc all end up calling `open(2)`. Feed one a byte stream and its first act
is writing that stream back to disk, so Rift hands over a path into a real `git worktree` — the one
belonging to the agent this work is for:

```
~/projects/charming-aurora            the main working tree — yours
  .rift/worktrees/a1                  agent 1's worktree, branch rift/a1
  .rift/state/rust                    what the Rust adapter writes
```

Every adapter driven for that agent is pointed at the same tree, so the Svelte adapter and the
TypeScript adapter reading one `.svelte` file are reading one copy of it. The tree is git's own
because the work in it gets committed and merged back when it is done — see
[the lifecycle](/docs/protocol#a-task-gets-a-worktree).

Two consequences for this seam. gRPC carries control and results, not source: `Analyze` says what
was found in files the compiler opened itself. And `Snapshot` names the tree in git's own spelling,
`worktrees/a1`, so an answer says which tree it was computed against and in what state.

The exception is a file the adapter *generated*. Nothing else can open that, so its bytes do cross —
`VirtualUnit` and `VirtualText`, in chunks, and Rift writes them into the consuming adapter's tree.

The path of that tree is the workspace's identity across this seam. One tree, one workspace, and Rift
never reuses a path once `CloseWorkspace` has taken it, so there is no minted handle to map back to a
directory.

<Callout>
  `state_root` is the adapter's, and Rift never reads it. Point `CARGO_TARGET_DIR`, `GOCACHE` and
  `tsBuildInfoFile` at it. It outlives any one workspace, which is what makes the second compile
  faster than the first.
</Callout>

## Who writes what

**Rift writes source. The adapter never does.** When you ask for a fix or a refactor, the compiler
computes the change and returns it — `Resolve` hands back a list of `Edit`, which is a byte
range and what replaces it. Rift applies those to the agent's worktree and tells the adapter about it
on the next `Refresh`.

Several adapters read that one tree, so an adapter writing into it would be writing under the others.
Keeping mutation on Rift's side is what makes one writer per worktree true, and one writer is what
lets `git diff` be the whole answer to what the agent changed — which is the thing validated and
committed at the end of the run.

A change that arrives as a value is also a change you can reject before it lands. Every formatter can
already work this way — `cargo fmt --emit=stdout`, `gofmt` without `-w`, `black --diff`,
`ruff format --diff`. Writing in place is the default of the command-line tool, not a limit of the
thing behind it.

**Compilers write anyway, and that is fine.** `cargo` puts `Cargo.lock` at the workspace root, npm
insists on `node_modules` beside the package it belongs to, and neither is redirectable. So the
adapter declares those paths in `Describe` as `WriteClaim`s, and Rift stops treating anything under them
as source: never analyzed, never diffed against the snapshot, never shown to an agent. That tree is
the one that merges back, so a compiler's scratch output must not read as the agent's work.

Declare only what will not move. Most build output redirects with an environment variable, and
redirecting it is better than claiming it, because a claim is a hole in what Rift can see.

## What crosses this seam

**A workspace is a cache; the worktree is not.** Losing an adapter costs a reopen and a cold compile.
The tree survives it — that is the agent's work, not the adapter's.

**The model is not defined here.** `Symbol`, `Leaf`, `File`, `Snapshot`, `Edit` and everything
else about code is generated from `core.json` into `core.proto`, so the messages below are only what
the seam itself adds. The model is documented once, in the [reference](/docs/protocol/reference).
