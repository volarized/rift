An adapter is how a language gets into Rift: a process wrapping that language's real compiler, and
answering questions about it. The Rift server drives it over **gRPC on a Unix domain socket**, and the
contract is `protocol/adapter.proto`.

## Transport

One Rift server starts its adapters, one per language, and owns them. Nothing else connects to them.
That decides more of this page than anything else: a workspace has exactly one party creating,
refreshing and closing it, so the adapter arbitrates nothing.

One adapter still holds several workspaces at once, because many agents work against one repository.
So in-flight work is bounded per workspace rather than per process, and the adapter interleaves
streams rather than draining one before starting the next — one agent's large analysis must not stall
everyone else on the connection.

Because the transport is gRPC, this contract carries no framing of its own. There is no envelope, no
request id, no operation name, no sequence number and no cancel call: an RPC method *is* the
operation, a stream is ordered, and a cancelled context or an expired deadline ends the work. Failures
are `google.rpc.Status`, carrying `Refusal` or `StaleState` in `status.details`.

## The adapter gets a working tree

Rift materializes the code and passes the path:

```
~/projects/charming-aurora          your worktree, Rift's to write
~/.cache/rift/trees/8f21c4          the Rust adapter's working tree
~/.cache/rift/state/rust            what the Rust adapter writes
```

That second path holds every file the snapshot names, laid out the way the repository lays them out.
It is a working tree in everything a compiler cares about, and Rift builds it with
`git checkout-index` for the commit the snapshot sits on, then overwrites the files the snapshot
reports dirty.

What it does not have is the `.git` that would make it a `git worktree`. A linked worktree leaves a
`.git` file pointing back at your real object store, and an adapter that wanted to could walk from
there into every branch you have, your remotes, and whatever credentials your git config holds. There
is no gitdir link here, so there is nothing to walk to.

rust-analyzer, gopls and tsc all want a filesystem. An adapter fed a byte stream would spend its first
act writing that stream back to disk, and Rift would have spent its own computing a delta `git diff`
already had. So Rift hands over a tree.

The path is the workspace's identity. One tree, one workspace, and Rift never reuses a path once
`CloseWorkspace` has taken it, so there is no minted handle to map back to a directory.

<Callout>
  `state_root` is the adapter's, and Rift never reads it. Point `CARGO_TARGET_DIR`, `GOCACHE` and
  `tsBuildInfoFile` at it. It outlives any one workspace, which is what makes the second compile
  faster than the first.
</Callout>

## Who writes what

**Rift writes source. The adapter never does.** When you ask for a fix or a refactor, the compiler
computes the change and returns it — `Resolve` hands back a list of `Edit`, which is a byte
range and what replaces it. Rift applies those to your worktree and tells the adapter about it on the
next `Refresh`.

This is the model LSP settled on, and the reason holds here too. A change you can see before it lands
is a change you can reject. And with several agents against one repository, an edit that arrived as a
return value affects the caller who asked for it, where an edit written to a shared tree affects
whoever reads next.

Every formatter can already do this — `cargo fmt --emit=stdout`, `gofmt` without `-w`, `black --diff`,
`ruff format --diff`. Writing in place is the default of the command-line tool, not a limit of the
thing behind it.

**Compilers write anyway, and that is fine.** `cargo` puts `Cargo.lock` at the workspace root, npm
insists on `node_modules` beside the package it belongs to, and neither is redirectable. So the
adapter declares those paths in `Describe` as `WriteClaim`s, and Rift stops treating anything under them
as source: never analyzed, never diffed against the snapshot, never shown to an agent.

Declare only what will not move. Most build output redirects with an environment variable, and
redirecting it is better than claiming it, because a claim is a hole in what Rift can see.

## What crosses this seam

**A workspace is a cache.** Losing an adapter costs time: Rift checks a fresh tree out and opens it
again.

**The model is not defined here.** `Symbol`, `Leaf`, `File`, `Snapshot`, `Edit` and everything
else about code is generated from `core.json` into `core.proto`, so the messages below are only what
the seam itself adds. The model is documented once, in the [reference](/docs/protocol/reference).
