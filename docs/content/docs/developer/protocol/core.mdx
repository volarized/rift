The core models describe source files and the facts providers return about them. The
[reference](/docs/developer/protocol/reference) links their generated schemas.

## Paths and files

[`ProjectPath`](/docs/developer/protocol/reference#ProjectPath) is a normalized UTF-8 path relative
to the workspace root. It uses `/`, contains no `.` or `..` component, and cannot name `.rift`,
where the server stores its own state. Normalized means Unicode NFC.

The index skips symlinks. A linked file answers under its own path when the source policy includes it.

## Source locations

[`TextRange`](/docs/developer/protocol/reference#TextRange) is a pair of half-open UTF-8 byte offsets.
Each provider converts its toolchain's positions to byte offsets, so ranges from different
providers use one scale.

[`nodes`](/docs/mcp#tool-nodes) returns the syntax nodes of one symbol, or of the declaration
holding one byte position, in pre-order. Each node carries its grammar kind, byte range, and source
text. Every source unit has a file node of kind `file` spanning all of it, the only node of a
file no syntax provider parses.

## Source discovery

Source resolvers run before syntax or semantic analysis. They inspect workspace files, manifests,
and lockfiles, then publish a source catalog of the project's source units and the packages the
project depends on. A resolver reads no package source, downloads no package, and does not change
the environment.

[`SourceUnitId`](/docs/developer/protocol/reference#SourceUnitId) names one unit in that catalog,
and a package file the global index answers from takes the same form:
`rift://source/cargo/crates.io/demo/src/lib.rs`. This package address names its manager,
registry and package, then the physical path in the package. It names no version: a read selects
the release whose bytes it answers through its `revision`. A project source address uses
`rift://source/project/` followed by its project-relative path. Logical symbol identities remain
separate from these physical addresses.

The key is never a digest. A [`Digest`](/docs/developer/protocol/reference#Digest) reaches the
wire only as a short witness where byte identity matters: the first eight hex characters of a
SHA-256. The server computes and compares the full digest internally, so it never travels whole.

A syntax node has no identity of its own. A [`Node`](/docs/developer/protocol/reference#Node) is
addressed by its place: node `index` of declaration `declaration` of `symbol`, counted in
pre-order from the declaration's item node at 0, or node `index` of its `unit` when no declaration
holds it, counted from the unit's file node at 0. A nested declaration's subtree counts toward the nested symbol alone, so an edit inside
one declaration leaves the indexes of every other declaration's nodes unchanged.

[`SourceLocationKind`](/docs/developer/protocol/reference#SourceLocationKind) names where a
declaration's source belongs: project, dependency, standard library, or external source.
[`SourceKind`](/docs/developer/protocol/reference#SourceKind) names how the source came to exist:
authored, generated, or synthetic for a declaration with no source unit. The two stay separate
because generated code can belong to the project or to a dependency.

A declaration in that package file carries both in its
[`SymbolOrigin`](/docs/developer/protocol/reference#SymbolOrigin), beside the package that owns
it:

```json
{
  "location": "dependency",
  "package": {
    "manager": "cargo",
    "registry": "crates.io",
    "name": "demo",
    "version": "1.0.0"
  },
  "source_kind": "authored"
}
```

A resolver publishes a new catalog revision when files, manifests, lockfiles, version pins, or
generated-source metadata change, and fact providers publish a new revision after they analyze
one. A read whose `scope` reaches packages reports a resolver that read less than the workspace
states as a `package_context_degraded`
[`ReadWarning`](/docs/developer/protocol/reference#ReadWarning), naming the resolver by its
manager name, such as `cargo` or `npm`.

## Semantic facts

Providers return facts in families: symbols, the syntax nodes that write them, relationships
between symbols, resolved types, diagnostics, and history. A family no provider can produce
refuses with `capability_unavailable`. Signatures and documentation travel on the symbol itself,
covered under the `types` family.

A search result carries the answer, `pagination`, and `warnings`. An exact symbol read carries
an `outcome` and the `revision` it was read at, and can carry a `declaration_cursor`. A condition the caller must
weigh - an index that lags the tree - arrives as a typed entry in `warnings`; the
[Reads](/docs/developer/protocol/mcp#reads) section in the MCP reference states the paging and warning
contract.

[`SymbolOrigin`](/docs/developer/protocol/reference#SymbolOrigin) keeps source location separate from
source kind. A synthetic symbol carries neither a location nor a package; dependency and
standard-library symbols can carry facts even when their provider cannot return source bytes.
The declaration's own source-catalog unit, where its location differs from the project, rides on
a [`get_symbol`](/docs/mcp#tool-get_symbol) declaration binding, addressed by `unit` instead
of the `path` a project declaration carries. The logical symbol identity remains separate from
that physical source address.

## History facts

The `history` family is resolved from the workspace's version-control history rather than from
the current tree. A [`SymbolHistory`](/docs/developer/protocol/reference#SymbolHistory) is one
symbol's history as edges. Each commit edge, a
[`HistoryEdge`](/docs/developer/protocol/reference#HistoryEdge) of kind `introduced_in`,
`changed_in`, `renamed_from`, or `removed_in`, names a
[`HistoryCommit`](/docs/developer/protocol/reference#HistoryCommit): the commit as a
`rift://revision/git/<commit>` revision, its author and time, and the path the declaration lived
at in it. A `co_changes` edge names another symbol and the number of listed commits that changed
both.

The history store keys each declaration change by the path and qualified name the commit held. A
[`SymbolId`](/docs/developer/protocol/reference#SymbolId) depends on the module layout of the tree
that holds the declaration, so the server binds those keys to symbols through the served tree: a
`renamed_from` edge names the path the declaration came from, and a co-changed declaration the
served tree no longer holds answers no `co_changes` edge.

The walk is bounded by the configured history depth. A commit that changed more than 256
declarations counts toward no `co_changes` edge, and one history answers at most 32 of them;
[`CoChangeTruncation`](/docs/developer/protocol/reference#CoChangeTruncation) counts what either
bound left out. The history rides a [`get_symbol`](/docs/mcp#tool-get_symbol) result when the
request asks for it.
